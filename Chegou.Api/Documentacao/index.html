Chegou | API de encomendas

Uma forma de apoiar a portaria no recebimento e na retirada de encomendas em condomínios.

Como funciona

Quando uma encomenda chega, o porteiro fotografa a etiqueta. A API usa inteligência artificial para ler os dados e sugerir o morador. A portaria confere a sugestão, registra o recebimento e acompanha as encomendas que ainda aguardam retirada.

  1. Fotografar: a etiqueta é enviada para leitura e o sistema apresenta os possíveis moradores.
  2. Confirmar: o porteiro escolhe o morador e registra a encomenda. Correções de nome podem ajudar em sugestões futuras.
  3. Acompanhar: a portaria consulta as encomendas pendentes.
  4. Retirar: a entrega é concluída com o código de retirada e o nome de quem a recebeu.

Estado atual: esta API é uma prova de conceito. O envio da notificação e do código de retirada ao morador ainda não está implementado, mesmo quando o status é NOTIFICADA. O código não é retornado no registro.

Integração com a API

Use a URL desta página como endereço base. As rotas de encomendas exigem o cabeçalho X-Condominio-Id com o código do condomínio, não o ID numérico. Esse código é uma chave de acesso: proteja-o como uma senha. A página inicial GET / não exige esse cabeçalho.

Nas requisições com corpo, envie JSON com Content-Type: application/json. Os exemplos abaixo são ilustrativos; IDs e códigos devem corresponder aos dados do seu condomínio.

Método e rotaFinalidade
POST /api/encomendas/etiquetaLeitura da foto e sugestão de moradores.
POST /api/encomendas/registrarRegistro da encomenda para o morador confirmado.
GET /api/encomendas/pendentesConsulta das encomendas aguardando retirada.
POST /api/encomendas/{id}/retirarConfirmação da retirada pelo código.

Rotas e exemplos

POST /api/encomendas/etiqueta

Envia uma foto JPEG da etiqueta em base64, sem o prefixo data:image. A leitura não registra a encomenda.

Corpo da requisição:

{ "imgBase64": "<foto em base64>" }

Exemplo de resposta 200:

{
  "fotoPath": "1/exemplo.jpg",
  "etiqueta": {
    "transportadora": "CORREIOS",
    "destinatario": "Maria da Silva",
    "bloco": "A",
    "apartamento": "101",
    "endereco_linha": null,
    "remetente": null,
    "rastreio": "AA123456789BR",
    "confianca": 0.95,
    "problemas": []
  },
  "unidadeId": 1,
  "nivel": "Alto",
  "candidatos": [{ "moradorId": 1, "nome": "Maria da Silva", "unidadeId": 1, "score": 1.0 }]
}

O nivel pode ser Alto, Medio ou Baixo; a resposta apresenta até cinco candidatos. Quando a unidade não é identificada, a busca considera os moradores do condomínio.

POST /api/encomendas/registrar

Confirma o morador. Envie o fotoPath e o objeto etiqueta devolvidos pela leitura, o moradorId escolhido e, quando disponíveis, o moradorSugeridoId e o scoreMatch.

Exemplo de corpo:

{
  "fotoPath": "1/exemplo.jpg",
  "etiqueta": {
    "transportadora": "CORREIOS",
    "destinatario": "Maria da Silva",
    "bloco": "A",
    "apartamento": "101",
    "endereco_linha": null,
    "remetente": null,
    "rastreio": "AA123456789BR",
    "confianca": 0.95,
    "problemas": []
  },
  "moradorId": 1,
  "moradorSugeridoId": 1,
  "scoreMatch": 1.0
}

Exemplo de resposta 200:

{ "idEncomenda": 3, "status": "NOTIFICADA" }

O status é NOTIFICADA quando o morador aceita notificações e RECEBIDA caso contrário. A notificação ainda não é enviada.

GET /api/encomendas/pendentes

Lista as encomendas do condomínio com status RECEBIDA ou NOTIFICADA. Não há corpo na requisição.

Exemplo de resposta 200:

[
  {
    "id": 3,
    "status": "RECEBIDA",
    "transportadora": "CORREIOS",
    "rastreio": "AA123456789BR",
    "recebidaEm": "2026-11-23T10:00:00",
    "morador": "Maria da Silva",
    "bloco": "A",
    "numero": "101"
  }
]

Quando não há encomendas pendentes, a resposta é []. A data usa o horário local do servidor SQL.

POST /api/encomendas/{id}/retirar

Substitua {id} pelo ID da encomenda e informe o código de retirada de seis dígitos e o nome de quem a retirou.

Exemplo de corpo para /api/encomendas/3/retirar:

{ "codigo": "889841", "retiradaPorNome": "Maria da Silva" }

Resposta 200:

{ "idEncomenda": 3, "status": "RETIRADA" }

Erros e limitações

Erros de negócio são retornados como 400 com mensagem em texto simples, por exemplo: Header não encontrado, Condominio não encontrado, Imagem não informada, Morador não encontrado, Encomenda não encontrada, Codigo de retirada inválido ou Encomenda já retirada ou devolvida. Uma falha de leitura tratada informa Não foi possível ler a etiqueta. Preencha manualmente.

JSON inválido ou campos obrigatórios ausentes também podem gerar 400 com detalhes de validação. Falhas não tratadas, como base64 inválido ou problemas de infraestrutura, podem gerar 500.

Para configuração, exemplos de teste e demais limitações da prova de conceito, consulte o README do projeto.
